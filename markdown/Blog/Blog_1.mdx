# Fixing the "params is a Promise" Error in Next.js 16: Why Dynamic Routes Break and How to Fix Them

Recently, while working on my blog built with Next.js 16 and the Modernize template, I ran into a frustrating issue that completely blocked access to individual blog post pages (routes like /blog/[slug]).

The console was throwing errors such as:

- "Route used `params.slug`. `params` is a Promise and must be unwrapped with `await`"
- "Cannot read properties of undefined" inside my markdown processing function

After some investigation, I realized this is an intentional change introduced in Next.js 15.2 and more strictly enforced in version 16. In Server Components for dynamic routes, the `params` prop is now a Promise. This supports advanced features like partial prerendering and streaming.

Trying to access `params.slug` directly returns undefined, which causes everything that depends on the slug (like loading markdown files) to fail.

The fix is surprisingly simple: treat `params` as a Promise by awaiting it in both the page component and the generateMetadata function.

This small adjustment immediately resolved all the errors. Blog posts started loading correctly, markdown content rendered as expected, and the site was fully functional again.

(Note: The "Invalid source map" warnings you might see with Turbopack on Windows are harmless. You can temporarily run `next dev --no-turbo` to hide them during development.)
